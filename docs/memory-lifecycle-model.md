# QuantClaw Memory-Like-A-Tree 生命周期模型

## 概述

QuantClaw Memory-Like-A-Tree 记忆系统采用了一种基于生命周期的管理模型，模拟植物的生长周期来管理记忆项。这个模型使得系统能够智能地跟踪、评估和维护记忆项目的重要性。

## 生命周期阶段

### 🌱 萌芽 (Sprout) - 0.7-0.8 置信度
- **描述**: 新创建的知识，刚刚被添加到系统中
- **特点**: 具有中等初始置信度，需要进一步验证和使用
- **行为**: 当被访问或使用时，置信度增加，有机会成长为绿叶状态

### 🌿 绿叶 (Green Leaf) - 0.8-1.0 置信度
- **描述**: 高价值、经常使用的知识
- **特点**: 高置信度，频繁访问，是系统中的重要记忆
- **行为**: 得到最好的维护，很少会被降级

### 🍂 黄叶 (Yellow Leaf) - 0.5-0.8 置信度
- **描述**: 中等重要性，使用频率下降的知识
- **特点**: 仍有一定价值，但不如绿叶重要
- **行为**: 可能会继续衰减成枯叶，也可能通过使用回升为绿叶

### 🍁 枯叶 (Dead Leaf) - 0.3-0.5 置信度
- **描述**: 低使用频率，价值下降的知识
- **特点**: 置信度持续降低，接近被清理的状态
- **行为**: 如果继续不被使用，将进入土壤阶段

### 🪨 土壤 (Soil) - < 0.3 置信度
- **描述**: 低价值或过时的知识，准备被清理或归档
- **特点**: 最低置信度，通常会被系统清理
- **行为**: 在完全删除前可能会被归档，以便新知识可能引用

## 生命周期转换机制

### 使用驱动的升级
- 当记忆项目被访问时，其置信度增加
- 高频使用的项目会从萌芽或黄叶状态升级为绿叶
- 相关性强的项目也会获得置信度提升

### 时间驱动的衰减
- 不常使用的项目会逐渐失去置信度
- 长时间不访问的项目会从高状态降级到低状态
- 置信度按时间和使用情况指数衰减

### 系统维护
- **每日衰减**: 执行置信度衰减，使不重要的记忆自然衰落
- **每日清理**: 移除低置信度项目，保持系统健康
- **自动归档**: 将有价值的历史记忆归档，防止完全丢失

## API 接口

```go
// 获取特定生命周期阶段的记忆项目
sprouts, _, err := memoryManager.GetSproutItems(10)      // 萌芽项目
greenLeaves, _, err := memoryManager.GetGreenLeafItems(10) // 绿叶项目
yellowLeaves, _, err := memoryManager.GetYellowLeafItems(10) // 黄叶项目
deadLeaves, _, err := memoryManager.GetDeadLeafItems(10)  // 枯叶项目
soilItems, _, err := memoryManager.GetSoilItems(10)      // 土壤项目

// 通用接口
items, confidences, err := memoryManager.GetItemsByState(Sprout, 10)
```

## 优势

1. **自然的衰减模型**: 模拟自然界中生命循环，更贴近人类记忆机制
2. **智能管理**: 自动识别和维护不同类型的记忆项目
3. **可观察性**: 清晰的生命周期状态便于调试和理解系统行为
4. **平衡性**: 在保留重要信息和清理冗余信息之间取得平衡

## 应用场景

- **知识积累**: 重要概念保持在绿叶状态，持续可用
- **上下文管理**: 相关记忆协同进化，形成知识网络
- **存储优化**: 自动清理过时信息，节省资源
- **学习适应**: 频繁使用的知识得到强化，不常用的知识自然淡忘
